What you have today

The current product is already a dependable local tracker.

The Python desktop app gives the job search one place to store applications and revisit status without relying on a web service or exposing private data.

LOG

Application capture

Posting URL, job ID, title, company, role type, pay notes, OA state, references, dates, status, and notes.

DEDUP

Duplicate prevention

Normalized URLs create stable IDs so repeated postings can be flagged before another application is saved.

LOCAL

Private storage

SQLite keeps application history on the machine and supports the local desktop workflow launched with Python.

VIEW

Basic review views

All-jobs table, row details, profile notes, resume notes, status updates, and a first dashboard are in place.

Dashboard model

Metrics should separate effort, response quality, and pipeline progress.

Am I applying consistently? Which applications get replies? Where am I stuck? What needs action next?
Volume

Application pace

Show applications by day and week so bursts, gaps, and momentum are visible without mixing in outcomes.

Quality

Hit-rate breakdown

Calculate replies divided by applications by source, role type, company, week, and location preference.

Progress

Status funnel

Track applied, OA, interview, rejection, offer, pending, and withdrawn states as one readable funnel.

Action

Follow-up queue

Surface portal checks, recruiter follow-ups, OA deadlines, and applications waiting too long for a reply.

Future email intelligence

Email reading should be narrow, explicit, and reviewable.

The future Gmail and Grok integration should only run after the user connects an account. It should match messages to tracked jobs, summarize relevant emails, classify outcomes, and ask for confirmation before updating important records.

  • Use read-only Gmail access until write actions are intentionally designed.
  • Keep token storage, mailbox scope, and audit logs visible to the user.
  • Separate email classification from final application status changes.

Offer comparison

Acceptance decisions need more than a salary number.

Total compensation

Base salary, bonus, signing bonus, equity, vesting schedule, benefits, relocation, and negotiation state.

Area reality

Cost of living, taxes, commute cost, housing pressure, local salary bands, and purchasing power.

Work model

Local, hybrid, remote, travel expectations, office cadence, schedule flexibility, and commute risk.

Decision frame

Compare upside, stability, timeline, growth, personal constraints, and acceptance deadlines in one view.

Build sequence

A staged roadmap keeps the tracker reliable before adding automation.

Now

Polish the tracker

Add edit flows, filters, follow-up dates, source fields, empty states, and clearer dashboard charts.

Next

Strengthen the data model

Add tests, schema migrations, backup and restore, event history, and import or export workflows.

Later

Add email response review

Design Gmail OAuth, token storage, message matching, Grok classification, and user-confirmed updates.

Future

Build offer acceptance tools

Model TC, benefits, location tradeoffs, work model, deadlines, negotiation notes, and final decision criteria.

Scope boundary

This page is a product report, not a feature implementation.

It documents what the app can do today and what it can become. It does not connect to Gmail, read messages, call Grok, calculate compensation, change the SQLite database, or alter the desktop app workflow.
